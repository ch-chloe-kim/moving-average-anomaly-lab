# 3단계 시뮬레이터 설계 — 이동평균 기반 이상 탐지

## 1. 산업 시나리오
- 메인(A): "명절 법인 주문 모니터링 센터" — 시간대별 주문 건수를 보며 급증(트래픽 폭주·매크로 주문)과 급감(결제·서버 장애)을 자동 감지
- 보조(B): 공장 설비 온도 센서 — 예제 버튼으로 제공

## 2. 알고리즘 규칙 (교과서 정의 + 명확한 예외 처리)
- 기준선 MA_t = 직전 N개 값의 평균 (현재 값 제외)
- 편차 d_t = |x_t − MA_t|
- 허용 범위(limit): 고정 모드 = 임계값(건), 비율 모드 = MA_t × p%
- 판정: d_t > limit → 이상 (x_t > MA_t 이면 급증, 작으면 급감), d_t == limit → 정상 (경계값은 정상)
- 워밍업: 처음 N개 시점은 판단 보류
- 옵션 "이상값을 기준선에서 제외": 켜면 직전 N개의 '정상 판정' 값(워밍업 포함)으로 평균 → CloudWatch의 학습 구간 제외 아이디어
- 비율 모드에서 MA=0이면 limit=0 → 0이 아닌 값은 모두 이상 (화면에 안내)

## 3. 입력값
| 입력 | 형식 | 범위 | 기본값 |
|---|---|---|---|
| 시간대별 주문량 | 쉼표 구분 정수 | 5~40개, 0~9999 | 100,110,90,105,300,95,100,20,105,110 |
| 윈도우 크기 N | 정수 | 2~10, 데이터 개수보다 작아야 함 | 3 |
| 임계값 방식 | 고정(건) / 비율(%) | - | 고정 |
| 임계값 | 정수 | 고정 1~9999, 비율 1~500 | 50 |
| 이상값을 기준선에서 제외 | 체크박스 | - | 끔(기본 SMA) |

잘못된 입력(빈칸, 문자, 음수, 개수 범위 밖, N ≥ 데이터 개수)은 빨간 오류 메시지 + 실행 버튼 비활성화

## 4. 예제 버튼
1. 기본 예제 — 급증·급감 각 1회
2. 기준선 오염 비교 — 체크박스 끄기/켜기로 오탐 차이 확인
3. 결제 장애(급감)
4. 설비 센서(B 시나리오)
5. 한계: 서서히 증가(드리프트) — 기준선이 따라가서 못 잡는 경우

## 5. 단계별 시각화
- 꺾은선 그래프(SVG): 실제 값(실선), 기준선(점선), 허용 범위 밴드(연한 띠), 점 색상(회색=워밍업, 초록=정상, 빨강=급증, 주황=급감)
- 현재 단계의 윈도우 N개를 반투명 박스로 강조
- 계산 패널: "기준선 = (100+110+90)/3 = 100 → 편차 |300−100| = 200 > 50 → 🚨 급증 이상"
- 컨트롤: 이전 / 다음 / 자동 실행 / 속도 슬라이더 / 끝까지 / 처음으로 + 진행 바

## 6. 결과 화면
- 요약 카드: 이상 n건(급증/급감), 정상 n건, 워밍업 n건
- 전체 계산 표: 시점·값·기준선·편차·허용 범위·판정
- 결과 해석 문장 (예: "5시 주문 급증 → 매크로 주문 확인 필요")

## 7. 설명 패널
- 이동평균 이상 탐지란? / 의사코드 / 장점과 한계 / 산업 사례(CloudWatch, Datadog, 출처 링크)

## 8. 코드 구조
- 핵심 함수 detectAnomalies(values, N, limitMode, threshold, excludeAnomalies) → 단계별 결과 배열 (순수 함수, 한국어 주석)
- 화면 그리기 render()와 분리
- 단일 index.html, 외부 라이브러리 없음
