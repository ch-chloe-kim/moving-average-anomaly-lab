# 2단계 조사 메모 — 이동평균 기반 이상 탐지 (주제 15)

## 1. 목적
- 시간 순서로 들어오는 수치(주문량, 서버 지표, 센서 값)에서 "평소와 다른" 값을 자동으로 찾아 경보를 낸다.
- 고정 임계값(예: 주문 500건 이상이면 경보)의 문제: 데이터 수준이 변하면 기준이 금방 낡는다 → 최근 데이터로 기준선을 계속 갱신.

## 2. 동작 원리 (단순 이동평균, SMA)
- 기준선 MA_t = 직전 N개 값의 평균 (x_{t-N} ~ x_{t-1}, 현재 값 제외)
- 편차 d_t = |x_t − MA_t|
- 판정: d_t > 임계값 → 이상, 아니면 정상
- 처음 N개 시점: 평균 낼 데이터 부족 → 판단 보류(워밍업)

### 손계산 예 (N=3, 임계값 50건)
| 시점 | 주문량 | 기준선(MA) | 편차 | 판정 |
|---|---|---|---|---|
| 1~3 | 100, 110, 90 | - | - | 워밍업 |
| 4 | 300 | (100+110+90)/3 = 100 | 200 | 이상 |
| 5 (이상값 포함) | 105 | (110+90+300)/3 = 166.7 | 61.7 | 이상(오탐!) |
| 5 (이상값 제외) | 105 | (100+110+90)/3 = 100 | 5 | 정상 |
→ 이상값을 기준선에 넣으면 다음 정상값까지 오탐 → 한계·설계 선택지로 활용

## 3. 산업 활용 사례 (출처)
- Amazon CloudWatch 이상 탐지: 통계·ML 알고리즘으로 정상 범위(밴드) 생성, 최대 2주 데이터로 학습, 배포 등 비정상 구간을 학습에서 제외 가능, 지속 재학습
  https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch_Anomaly_Detection.html
- AWS 블로그: 소매 주문이 예상 기준선 아래로 떨어지면 세일 등 자동 조치하는 동적 알람 튜토리얼
  https://aws.amazon.com/blogs/mt/how-to-set-up-cloudwatch-anomaly-detection-to-set-dynamic-alarms-automate-actions-and-drive-online-sales
- Datadog Anomaly Monitor: basic(지연 롤링 분위수, 계절성 없음) / agile / robust 알고리즘. 계속 성장하는 지표는 고정 임계값이 낡는다는 설명
  https://docs.datadoghq.com/monitors/types/anomaly/
- 주의: 실제 서비스는 계절성·추세를 반영한 ML 모델 사용. 이동평균은 그 핵심 아이디어(최근 데이터 기반 기준선 + 허용 범위)를 단순화한 것.

## 4. 장점과 한계
장점: 계산 단순·빠름(실시간 가능), 설명 쉬움, 데이터 수준 변화에 자동 적응
한계:
- 윈도우 N 선택 민감(작으면 노이즈 민감·오탐, 크면 반응 느림)
- 워밍업 구간 판단 불가
- 이상값이 기준선을 오염 → 오탐 또는 이상의 "정상화"
- 계절성 미반영(명절 저녁 피크도 이상으로 판정 가능)
- 서서히 변하는 이상(드리프트)은 기준선이 따라가서 못 잡음
